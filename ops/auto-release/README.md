# Автоматическая выкладка AELITA

Рабочая ветка для заданий — `ops/auto-release`. Запуск начинается при добавлении или изменении `ops/auto-release/release.json`. Запрос формирует сборщик утверждённого выпуска после загрузки обоих ZIP в закрытое хранилище. В GitHub передаются версия, контрольные суммы и решение по денежному этапу.

Автоматизация запускает полный штатный процесс из этого пака. Она использует текущий обработчик функций Яндекса, сверяет его отчёт перед публикацией сайта и выполняет проверки из пака. Если штатный сценарий требует ручной настройки, разберите её через Termux. После запуска с телефона дождитесь его отчёта перед отправкой следующего запроса в Actions.

## Подключение

Создайте окружение `aelita-production` в GitHub для ветки `ops/auto-release` и разрешайте запись в эту ветку только выпускающим. Для запуска без подтверждений оставьте обязательных проверяющих выключенными. Подключите отдельные служебные доступы в окружении.

| Имя | Назначение |
| --- | --- |
| Переменная `AELITA_RELEASE_BUCKET` | Закрытый бакет с выпусками |
| Секреты `AELITA_YC_S3_KEY_ID` и `AELITA_YC_S3_SECRET` | Чтение закрытых выпусков и штатный доступ к объектам выкладки функций в Яндексе |
| Секрет `AELITA_GITHUB_PAGES_TOKEN` | Токен служебной учётной записи для записи в aelita с правом Contents: Read and write, чтобы коммит запускал Pages |
| Секрет `AELITA_CLOUDFLARE_TOKEN` | Доступ к указанным в выпуске воркерам и их KV. Требуется для выпусков с ботом |

Сборщик выполняет `python3 ops/auto-release/release.py stage <папка_выпуска> <номер>`. Команда проверяет core и deploy, загружает их в закрытый бакет под `releases/pack-vNNNN/` и выводит JSON. Сохраните этот JSON в `ops/auto-release/release.json` и отправьте коммит в `ops/auto-release` только после успешного завершения команды.

Параметр `--money` разрешает денежный этап именно этого выпуска. По умолчанию денежные функции можно выложить отдельно через Termux. В публичных журналах видны результаты этапов. Распакованный пак и журналы штатного скрипта удаляются после выполнения.

## Termux

Полная выкладка с подтверждением:

```bash
cd ~ && ~/deploy_aelita.sh
```

Отдельный компонент выбирается параметром `site`, `functions` или `bot`. Для сверки состояния используйте `~/deploy_aelita.sh doctor`. Копии рабочих данных продолжают сниматься через Termux.
